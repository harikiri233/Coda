# 排查失败的 pytest 用例

1. **只跑失败的用例**，拿到完整报错：`uv run pytest 路径::用例名 -x -q`（没有 uv 时用 `python -m pytest`）。
   全量输出很长时先用 `--tb=short`，需要细节再 `--tb=long -vv`。
2. **读报错要从下往上**：最后一行是异常类型和信息；往上找第一个位于项目代码（不是 site-packages）里的栈帧，那是出问题的位置。
3. **分清类型**再动手：
   - `ImportError` / `ModuleNotFoundError`：查包名、相对导入、`__init__.py`，以及是否需要 `uv sync`；不要靠改 `sys.path` 绕过。
   - `AssertionError`：对照断言两边的值，先判断是实现错了还是测试的期望过时了。没有充分理由不要改测试去迁就实现。
   - `fixture 'x' not found`：查 `conftest.py` 的位置和作用域。
   - 只在全量运行时失败：多半是用例之间共享了状态（全局变量、文件、环境变量、单例），用 `-p no:randomly`、单独运行对比。
4. **读相关代码**：用 grep 找被测函数，用 read_file 读实现和测试，搞清楚预期行为。
5. **最小修改**：只改导致失败的部分；修完先重跑这个用例，再跑整个测试文件，最后跑全量，确认没有引入新的失败。
6. 修不好时如实说明：贴出关键报错，说明已经排除的原因和下一步的猜测。
